## ⚠️ 必读：这个工具要装一个按键驱动，它是什么、安不安全

**一句话：它叫 Interception，是一个开源、免费、公开可审计的键盘鼠标驱动，装机量很大（大量自动化测试、按键精灵类需求都在用），不是外挂作者写的黑箱。** 它不做任何联网、不读游戏内存、也不藏在暗处，装完之后就是一个普通驱动，你在设备管理器里能直接看到它。**装它是为了「发按键」，不装发不出去 —— 就这么一个用途。**

### 为什么非装不可

先说清楚这个工具是怎么操作的：它**不读游戏内存、不改游戏文件**，做法跟人一样 —— 看游戏画面 → 认出怪和自己在哪 → 按键盘。

问题就出在最后一步「按键盘」。

**背景：上游台服版用的是 KMbox，一种需要单独花钱买的硬件外设**（插在电脑上的一个盒子，由它替你在硬件层面"冒充"键盘）。台服能用，是因为人家走的是这条路。

我试下来发现，**用 Interception 这个软件驱动方案可以绕开 KMbox** —— 不需要额外买任何硬件，装一个驱动就够。这是本 fork 相对上游最大的实现差异之一，也正是它「免安装包解压即用」的前提。

那为什么普通按键不行？

Windows 有两套发按键的路子：

| 路子 | 原理 | 游戏能不能识别 |
|---|---|---|
| 普通模拟按键（`SendInput` 等） | 由程序伪造，**声明**"这是键盘按的" | 很多游戏会识别出这是伪造的，直接忽略 |
| **Interception（本项目用的）** | 走 Windows 的驱动层，按键**从驱动进入系统**，和真键盘按下的路径一致 | 系统层面就是真实输入，**不用买硬件也能达到同样效果** |

打个比方：普通模拟按键像是**别人替你签了个名**，笔迹不对就会被认出来；Interception 则是**把签名这个动作本身交给了系统底层去做**，系统收到时它和真人签的没有区别。

所以不装驱动会怎样？**程序照常能打开、也能点「开始」，但按键一个都送不进游戏 —— 表现就是「角色一动不动」**。这不是 bug，是这一步没做。

### 它安全吗

这是你最该关心的，逐条说：

- **开源可审计**：Interception 的源码、二进制、安装包全部公开放 [在 GitHub](https://github.com/oblitum/Interception)（`oblitum/Interception`，MIT/BSD 类宽松协议，star 上万），世界上任何人可以去看它到底干了什么。**它没有闭源部分，也不是破解版**；
- **不做坏事**：它不联网、不上传数据、不采集你的账号信息。它的功能就是**把按键送进系统**，仅此而已 —— 一个只干这件事的驱动，没有别的地方可用；
- **可卸载、可回滚**：装错了、不想要了，用同一条命令 `install-interception.exe /uninstall` 就能卸掉，重启即恢复；
- **它不是外挂本体**：驱动只管"发按键"，**判断打哪只怪、走哪条路线的逻辑在本程序里**。驱动本身不知道你在玩什么游戏，你把它装在记事本上也是同样的用法。

**它和游戏外挂的本质区别**：内存挂、注入挂要**钻进游戏进程**去改数据，那种才危险。Interception 从头到尾**没碰游戏进程一个字节**，它只是让系统按了几下键盘。

> ⚠️ **必须说明的一点**：驱动本身安全，**不代表用它玩游戏就不违规**。游戏官方禁止的是"自动化操作"这件事，不在于你用什么方式实现。**它是驱动还是 KMbox，对封号判定没有豁免作用** —— 这一点请务必知悉，风险仍由你自己评估。

### 怎么装

**这一步不能跳过。** 驱动是独立的，装完程序**还要单独装它一次**。

1. 打开 https://github.com/oblitum/Interception/releases/latest ，下载 `Interception.zip` 并解压；
2. 进解压出来的文件夹，在地址栏输入 `cmd` 回车（用**管理员身份**打开命令提示符）；
3. 执行：
   ```
   install-interception.exe /install
   ```
4. **重启电脑**（不重启不生效），再打开本程序。

装对了的话，程序日志里不会再出现 `Interception 初始化失败`。

> ✅ **Win11 上看到报错别慌**：安装时如果最后卡在 `Could not write to \system32\drivers`，**这其实是装成功了**，不用重试也不用管它。这个报错是安装器写完驱动后清理临时文件失败留下的（[上游 issue #215](https://github.com/oblitum/Interception/issues/215)），驱动本体已经就位——**直接重启电脑，然后开本程序验证即可**。判断装没装成的唯一标准是：程序日志里不再出现 `Interception 初始化失败`，以这个为准，不要以安装时的报错为准。

> 💡 从 **v1.0.6** 起，驱动没装的话，你点「开始」时程序会**直接弹窗告诉你怎么装**，不用自己找。
>
> ⚠️ 极少数机器装完会出现键鼠异常。万一遇到：开机进**安全模式**，删掉 `C:\Windows\System32\drivers\` 下的 `keyboard.sys` 和 `mouse.sys` 即可恢复。装之前先记一下这条。
>
> 想卸载：`install-interception.exe /uninstall`，然后重启。

## 与上游的差异

国服客户端与台服 Artale 不是同一套东西，以下改造不是可选优化，而是必须：

| 项 | 台服上游 | 国服本 fork |
|---|---|---|
| 客户端 | 原版 2D 客户端 | **Unity 重制版** |
| 角色定位 | 可用组队血条 | 组队血条**不可用**，改用**角色名标签**定位 |
| 符文系统 | 有 | **无**，相关逻辑已删 |
| 创角掷骰 | 有 `AutoDiceRoller` | **无**，工具已删除 |
| 地图定位 | 全屏截图方案 | 小地图方案，旧实现已整批删除 |
| 反作弊 | — | 客户端带**反挂机（AntiMacro）验证**与三层反作弊 |
| **按键模拟** | **KMbox 硬件外设**（需额外购买） | **Interception 软件驱动**（开源免费，[说明见上](#driver)） |
| **自动喝药** | 宠物技能 / 手动 | **血蓝监控自动喝药**（识屏读血条，环境锁定 1366x768 窗口化） |

## 本仓库的优化点（UIoptimized 版）

> 这一节列的是**本仓库相对 [上游 Aynamuk/MapleStoryAutoLevelUp-CN](https://github.com/Aynamuk/MapleStoryAutoLevelUp-CN) 多出来的东西**。
> 每一条都在 `.github/workflows/ci.yml` 里有对应的自检（共 53 项），条目数本身也被自检盯着 —— 不是"写完了就算数"。

### 界面（这个 fork 的主线）

| 优化 | 说明 |
|---|---|
| **界面只留日常要动的键** | 不常改的键从界面收起来（`src/ui/ui.py` 的 `ADV_FIELD_HIDE`），要调直接改 `config/config_custom.yaml`；同一判据只写一处，避免"改一处漏一处" |
| **怪物识别页** | 识别阈值、感知范围、交战余量等可视化调整，键名中英对照（`eng_to_cn`） |
| **地图 ↔ 怪物映射** | 每张图登记该图会出哪些怪（`config_data.yaml` 的 `map_mobs_mapping`），模板只加载这些，减少误认与开销 |
| **🎥 示范录制** | 「你自己玩，它录」：键盘静音、引擎照算，落 `debug/demo/*.jsonl.gz`；离线跑 `python -m tools.analyze_demo` 得到「人出手时离怪多远 / 引擎想打而人没打 / 人打了而引擎没想」的分位数与分歧清单 |
| **关闭挂机二次确认 · F12 关闭** | 挂机中误点关闭会弹确认；F12 也能关，避免手滑停摆 |
| **配置深合并** | `config_default.yaml` 铺底 + `config_custom.yaml` **只写改动项**；主界面「配置方案」另存个人方案。升级后没写过的键会自动跟随新默认值，不会整段替换丢新键 |

### 识别与出手

| 优化 | 说明 |
|---|---|
| **检测降频** `every_n_frames` | 早期真机一帧 552ms，其中怪检测 502ms（91%）⇒ 只有 1.8fps；降频后中间帧沿用上次结果，不用每帧重算 |
| **感知框放大** `detect_range_scale(_y)` | 旧实现感知框 = 攻击框，在 1366×768 客户区里只占 13%，真机 12 帧 53 只怪里 46 只（87%）在框外 ⇒「身边有怪不认」 |
| **轮廓 + 颜色校验** | `mode: contour_only` 整个 ROI 只预处理一次（旧实现每张模板重做一遍）；`verify_color` / `verify_color_tol` / `verify_min_ratio` 过滤误报；支持左右镜像模板变体 |
| **攻击框外交战** `approach_mob` | 框外还有目标就主动靠近；「连续两次都看见」才算确认，防抖 |
| **停下来打完再走** `stop_to_attack` | 巡逻中遇到目标先站定打完再走（`stop_attack_clear_frames` / `_clear_s` / `stop_attack_timeout_s` / `target_hold_s`） |
| **交战期收窄扫描** `engaged_scan` | 站定打怪时把搜索框收成攻击框 ± 余量，实测单次 17.1ms → 7.2ms（-58%） |

### 路线、梯子与「走丢」

| 优化 | 说明 |
|---|---|
| **多段路线 + 回正线** | `route1..4` + `route_home`（可按 F6 补录 / 🖊 手绘）：偏离 → 回正 → 回主线，带进入/保持/退出/去武装一套状态机与 `[回正·小结]` 留痕 |
| **梯子与绳子** | `ladder_still_s`（旗标为真就一直让路 ⇒ 改成"最近 N 秒真没动才不让路"）、`ladder_leave_x`（±2px 抖动会误判"已离开梯子"）、`rope_nudge_*`（脚下按了 N 秒没上去就往左/右蹭一下） |
| **目标像素过滤** `goal_pixel_skip` | 治「站在本段终点正下方 8px、引擎死发 `goal`、原地冻死 5 分钟」；2026-10-14 又修两处：侧向被拒后先在搜索框内换可用像素（换不到才退回老行为，不再直接甩给回正/救援）；真绳梯不再被「地面伪灰」判成假（参照物原来只看回正线，全图只有 9 个竖向像素） |
| **回正入口可达性闸** | 回正线最近像素在搜索/救援半径之外时**不进**回正（否则进去当帧就"接不上"退出 + 去武装，纯 churn） |

### 名字定位（国服唯一可用的角色定位方式）

| 优化 | 说明 |
|---|---|
| **丢名字放宽** | `relax_ratio` / `relax_max_jump`：严格分数不中时，在上次命中位置附近按倍数放宽采信 |
| **位置缓存** | `pos_cache`：先在上次位置 ±50px 内搜，分数够好就不再全图搜 |
| **丢名字取证** | `miss_dump`：把丢名字那一帧存下来，便于事后判断是"被挡"还是"识别不出" |
| **模式回归修复** | v1.0.11 把 `mode` 默认改成 `white_mask` 是一次回归（模板退化成常数 ⇒ 定位漂移）；已撤回 `grayscale`，并在 `load_config` 里自动纠正存量配置 |

## 环境要求

- Windows 10 / 11（**不支持虚拟机**，也不支持 macOS）
- Python 3.12
- 依赖见 `requirements.txt`：

```bash
pip install -r requirements.txt
```

其中 `interception-python` 用于内核级按键模拟，需要管理员权限运行；`windows-capture` 用于抓帧。

> ⚠️ **两个依赖的门槛不一样，别混为一谈**（2026-09-27 实测确认）：
>
> | 用途 | 依赖 | 额外要装系统组件吗 |
> |---|---|---|
> | **发按键** | `interception-python` | **要** —— 它是内核驱动的 Python 封装，光 pip 装包不够，还得单独下载安装 [Interception 驱动](https://github.com/oblitum/Interception/releases/latest) 并重启电脑 |
> | **看画面** | `windows-capture` + `opencv-python` | **不要** —— `windows-capture` 调的是 Windows **自带的** Graphics Capture API，`opencv` 是纯算法库（只处理内存里的图片数组） |
>
> 缺驱动的症状是「程序能开、能点开始，但角色一动不动」——见 `src/input/InterceptionController.py` 的 `driver_status()`。
> 抓帧唯一的限制是**游戏必须窗口模式**（系统接口抓不到独占全屏），与驱动无关。

### 自动喝药的环境要求（2026-09-27 新增功能）

**一句话**：游戏要**窗口化 + 1366x768 + Windows 缩放 100%**，三条都满足才能用自动喝药。

**为什么这么严**：自动喝药靠"看画面上的血条"来判断。血条的位置是一个像素一个像素量出来的，窗口大小或缩放一变，量的位置就不对了，读出来的血量就是错的。与其让它读错，不如把环境卡死在一套量准了的配置上。

| 要求 | 怎么设 |
|---|---|
| 游戏分辨率 | 游戏内设成 **1366x768**，并且**窗口化**运行 |
| Windows 缩放 | 「设置 → 系统 → 显示 → 缩放」设成 **100%** |
| 双屏用户 | 如果两个屏幕的缩放不一样，把游戏窗口拖到**主屏幕**上 |

> 游戏的最大化按钮是灰的、点不了，不用管；**全屏不行** —— 全屏会直接使用显示器的物理分辨率，就不是 1366x768 了。

环境的这三条不同时满足时，工具**会拦住并告诉你该怎么改**（不会悄悄读错）。不满足时挂机打怪照常，只是不自动喝药。

> 如果工具提示"游戏画面大小不对"，把上面三条逐条对一遍即可 —— 尤其注意**缩放 100%** 这一条，多屏用户的画面尺寸对不上多半是它造成的。

## 快速开始（源码运行）

> 用免安装包的**跳过这一节** —— 你要做的是 [用户版说明](README_用户版.md) 里的四步。

1. 启动国服怀旧服客户端，切换到**窗口模式**
2. 打开游戏左上角的**小地图**（角色定位依赖它）
3. 把角色走到要挂机的地图
4. 双击 `启动界面.bat`，在主界面「配置方案」里调好按键与地图
5. 按 `Start` 或 `F1` 开始

界面没反应时双击 `诊断启动.bat`，它用带控制台的 Python 启动，报错会留在窗口里。

> **首次使用需要自己做模板**：`monster/`（怪物模板）、`minimaps/`（地图与路线）、`nametag/`（角色名标签）三个目录出厂是空的。上游台服的模板与国服画面不通用，必须用本项目的工具从国服真机截图重做。界面上的 F2（标定名字）/ F3（截怪）/ F4（录路线）就是干这个的 —— 这四步的**面向用户版说明**见 [README_用户版.md](README_用户版.md)。

| `诊断启动.bat` | 带控制台启动，用于看报错 |
| `停止界面.bat` | 关闭界面 |

三个 bat 都不写死 Python 路径，按以下顺序自动查找：环境变量 `MAPLEBOT_PY` → PATH 里的 `pythonw.exe` / `python.exe`。想固定用某个虚拟环境：

```bat
setx MAPLEBOT_PY "D:\你的venv\Scripts\pythonw.exe"
```

### 发版：完整包 + 增量补丁

> **⚠️ 发版前必须先过 CI 门禁**（2026-09-27 加，因一次真实翻车）：
>
> ```bash
> python -m tools.verify_ci_green
> ```
>
> 它按**当前 commit 的 sha** 查最近一次 CI，只有结论是 `success` 才放行。
> 不是 success（含还在跑、查不到、failure）一律拦住并指出怎么查。
>
> **为什么必须这一步**：本地 13 项自检绿 **不代表** CI 绿 ——
> 本地有 CI 环境没有的文件（典型：`config/config_data.yaml` 是用户数据、
> 不进仓库），这类问题本地永远测不出来。2026-09-27 发 v1.1.0-beta.1 时
> 就是"本地绿 → 直接发版 → CI 随后变红"，说明发版流程里当时**没有看 CI 这一步**。
> ⇒ 现在做成机器检查，不靠人记得去点 Actions 页面。

完整包约 **106MB**，但其中 250MB+ 是 Python 运行时与第三方库（`_internal/`），**我们自己的代码只有约 6MB**（内嵌在 exe 里）。所以小改动不该让用户重下整个包 —— 发版时**两个都传**：

```bash
# 1) 打完整包（照常）
python -m tools.make_release_zip "dist/冒险岛自动练级" "MapleStoryAutoLevelUp-CN-vX.Y.Z.zip"

# 2) 生成增量补丁（只含变化的文件，实测约 6MB）
#    ★ 用 --universal：一份覆盖**所有**比 --to 旧的版本，
#      不必为 v1.0 / v1.0.1 / v1.0.2 各发一份（那只会让用户困惑）。
#      原理：业务代码（600+ 模块）全内嵌在 exe 里，补丁整包替换 exe，
#      所以不论从哪个旧版本出发，需要的东西完全一样。
python -m tools.make_patch --to v1.0.3 --universal \
    --dist "dist/冒险岛自动练级" --out "patch-to-vX.Y.Z-universal.zip"

# 3) 两个附件一起传
gh release upload vX.Y.Z MapleStoryAutoLevelUp-CN-vX.Y.Z.zip patch-to-vX.Y.Z-universal.zip
```

补丁 zip 里含 `patch.json`（版本、适用版本清单、sha256）和 `应用补丁.bat`（老用户双击即完成覆盖，会先把被覆盖的文件备份到 `_backup_补丁前`）。

**两条硬约束（脚本会自检并拒绝违规的补丁）**：

1. **依赖有变化时不许发补丁**（`requirements.txt` 等变过）—— 那时用户 `_internal/` 里的库对不上，必须走完整包。`--universal` 会逐个检查所有旧版本。
2. **补丁文件必须放在 zip 的子目录 `_补丁文件/` 里**，不能与用户程序同级 —— 同级会导致「解压即覆盖」：用户还没双击 bat，程序就被改了，备份拿到的是新文件（还原无意义），且解压中断会留下半新半旧的损坏安装（2026-09-27 实测复现）。

补丁**不会包含**用户自己的数据：`config/config_custom.yaml`、`config/config_data.yaml`、`log/`、`minimaps/`、`monster/`、`nametag/` 一律排除，覆盖升级不会毁掉配置和路线。


## 配置体系

- `config/config_default.yaml` —— 全部默认值与注释说明（**基准**，一般不改）
- `config/config_custom.yaml` —— 用户配置的出厂回退值
- `config/config_data.yaml` —— 地图 / 怪物登记表（录完路线、截完怪会自动写入）
- 主界面「配置方案」另存的自定义方案（如 `config/你的方案名.yaml`）—— **个人数据，不要提交到仓库**，`.gitignore` 已按规则挡住

配置的加载语义是**深合并**：`config_default.yaml` 铺底，你的方案覆盖改过的键。所以方案文件里只写你改过的项就够了。

## 自检脚本

`tools/verify_*.py` 是一批离线自检，不开游戏也能验证核心逻辑：

```bash
python -m tools.verify_load_config        # 配置加载链路（异常不静默）
python -m tools.verify_navigation         # 导航与路线

python -m tools.verify_recorder_action    # 录制器动作读取
python -m tools.verify_bars_potions       # 血蓝监控 + 自动喝药（含"不在前台不发键"回归）
python -m tools.verify_ci_green_check     # 发版门禁的判据本身（离线，不联网）
```
